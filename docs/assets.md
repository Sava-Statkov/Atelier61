# Снимки, видео и съдържание — как се добавят

Съдържанието е в `src/content/*.ts` (типизирани файлове). Страниците не се пипат, за да се добави творба, текст, снимка или видео.

## Правила за проверка

Всеки запис има `verification`:

| `status` | Значение | В публичния сайт |
| --- | --- | --- |
| `confirmed` | Потвърдено от художника или семейството | Да |
| `sourced` | Публикувано в цитиран източник, още не е потвърдено от художника | Да, с бележка под линия към източника |
| `unconfirmed` | Трябва да се провери | Не |
| `placeholder` | Работно място за разработка | Не |

- `sources` сочи към записи от `src/content/sources.ts`.
- `note` описва какво точно е несигурно; вижда се само в работната версия.
- Полетата на творба, които още не са проверени, се изброяват в `pending` (напр. `["date", "dimensions"]`) и се скриват в публичния сайт.
- Историите имат отделно `editorial`: само `published` излизат публично.
- Цитатите (`quotes.ts`) са **дословни** и винаги с източник. Не се перифразират в кавички и не се измислят.

`npm run dev` показва всичко с бележки за редакцията. `npm run build`, после `npm start`, показва само публикуемото. За да видите публичната версия по време на разработка, в PowerShell: `$env:CONTENT_MODE="published"; npm run dev`.

`npm test` проверява дали всички препратки (цикли, изложби, цитати, източници) съществуват и дали нищо „sourced“ не е без източник.

## Творби

1. Поставете снимката в `public/media/artworks/<slug>/`, напр. `public/media/artworks/primer/primer.jpg`.
   - JPEG или WebP, sRGB, дълга страна 3000–4000 px (повече е безсмислено за уеб; оригиналите в TIFF пазете в `media-originals/`, която не се публикува).
   - Снимка на цялата творба без рамка и без фон (или с равномерен фон), правилно изправена, без отблясъци.
   - Детайли — отделни файлове или отбелязани области (`details`, вижте по-долу).
2. Добавете запис в `src/content/artworks.ts` (стойностите по-долу са само пример за формата):

```ts
{
  slug: "primer",                       // латиница, малки букви, тирета — става адрес /tvorbi/primer
  title: { bg: "Заглавие на творбата" },
  date: { year: 2000 },                 // или { start: { year: 1999 }, end: { year: 2000 } }; без дата — пропуснете
  technique: { bg: "масло върху платно" },
  media: ["oil"],                       // за филтъра: oil, watercolour, ink, graphic, glass, caricature, drawing, mixed, set-design, illustration
  dimensions: { heightCm: 100, widthCm: 80 },
  series: ["kamennata-kniga-na-balgariya"],
  summary: { bg: "1 до 3 изречения за творбата — показват се под нея на страницата „Творби“." },
  images: [
    {
      src: "/media/artworks/primer/primer.jpg",
      alt: { bg: "Какво се вижда на картината — описание, не оценка" },
      rights: "artist",                 // "artist" | "licensed" | "unknown" (unknown никога не се публикува)
      credit: "Снимка: …",
    },
  ],
  details: [
    {
      id: "detail-1",
      region: { x: 0.42, y: 0.1, width: 0.2, height: 0.18 }, // област от снимката, в части от 0 до 1
      caption: { bg: "Какво има в детайла" },
      verification: { status: "confirmed" },
    },
  ],
  enquiries: true,                      // дискретна връзка „Запитване за творбата“ (само ако има имейл в site.ts)
  verification: { status: "confirmed", confirmedBy: "семейството на художника" },
}
```

3. `npm run media` (пуска се и автоматично преди `dev` и `build`) чете размерите на снимките и прави малко размито превю → `src/content/generated/media.json`. Не е нужно да въвеждате ширина и височина.

Next.js прави AVIF/WebP в нужните размери и ги зарежда мързеливо. Голямата снимка за „Разгледай отблизо“ се изтегля едва когато посетителят отвори лупата.

**Права:** не публикувайте снимки на трети лица (медии, галерии, фотографи) без писмено разрешение. Снимките от статиите, използвани при проучването, не са в проекта.

## Снимки на художника, ателието и процеса

**Портрет в „Повече за художника“:** сложете снимката в `public/media/photos/` и я посочете в `site.portrait` (`src/content/site.ts`): `{ src: "/media/photos/rumen-statkov.png", alt: { bg: "…" }, rights: "artist", credit: "Снимка: …" }`. Може JPG, PNG, WebP или AVIF; сайтът сам я компресира. Показва се малка, в портретен формат, под заглавието; без снимка там стои празна рамка с надпис.

`public/media/photos/…` — използват се и в истории, описания на творби и цикли чрез блок `{ type: "image", image: { src, alt, rights, credit }, caption }`. Снимка с `rights: "unknown"` не се показва.

## Следи от творбите (`public/media/marks/`)

За следващата итерация: сканирани фрагменти от истински творби (линия с туш, мазка, щрих), с прозрачен фон (PNG/WebP). От тях ще се правят изразителните наслоявания в оформлението. Никакви генерирани или стокови „петна от боя“.

## Видео: интервюто

Записът е в `src/content/films.ts`. Докато `status` е `"planned"`, плейърът показва празен екран с текст „Интервюто предстои да бъде заснето.“

Когато видеото е готово:

1. **Постер:** `public/media/film/intervyu/poster.jpg` (16:9, кадър от филма) → `poster: { src, alt, rights: "artist" }`.
2. **Видео файлове:** големите файлове не са подходящи за `public/` — качете ги на видео хостинг или CDN (напр. Bunny Stream, Cloudflare Stream, Mux) и сложете адресите в `sources`. Препоръка: MP4 (H.264) 1080p ≈ 6–8 Mbps; по желание WebM/AV1 като първи източник.

```ts
sources: [{ src: "https://…/intervyu-1080.mp4", type: "video/mp4" }],
```

3. **Субтитри:** WebVTT файлове в `public/media/film/intervyu/` → `tracks: [{ src: "/media/film/intervyu/bg.vtt", srclang: "bg", label: "Български", kind: "subtitles", default: true }]`. По-късно — английски.
4. **Части:** `chapters: [{ start: 95, title: { bg: "Шаржовете в парламента" }, series: ["sharzhove-na-prehoda"] }]` — всяка част може да води към цикли, творби и истории.
5. **Текст на разговора:** `transcript: [{ start: 95, speaker: "Румен Статков", text: { bg: "…" } }]` — точният текст от записа, не преразказ.
6. `status: "available"` и `durationSeconds`.

Видеото никога не започва само и не се зарежда предварително: първо се показва постерът, а файлът се иска едва след „Пусни видеото“.

Ако видеото е в YouTube или Vimeo, кажете — може да се добави вграждане с „фасада“ (зарежда се чак при натискане).

## Цикли, изложби, летопис, истории

- `series.ts` — цикли; `composition` и `room` определят как се окачват и в каква среда.
- `exhibitions.ts` — изложби и изпълнения с дата и място. Покана за бъдещо събитие — само за реално потвърдено събитие.
- `timeline.ts` — събития от живота, които не са изложби. Без дата → излиза под „Без точна дата“; не гадаем години.
- `stories.ts` — истории, които започват от въпрос, детайл или цитат и водят към творби и цикли.
- `site.ts` — контакти (`email`, `phone`, `facebook`), кратката биография, коя творба е на началната стена.
